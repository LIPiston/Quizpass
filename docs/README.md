# Quizpass 文档

**用途**：让玩家自己申请进入服务器，把「加白名单」这件事从管理员手动执行变成玩家自助 —— 玩家打开 Quizpass 网页，填上**游戏内名称、游戏方式（正版 / 皮肤站）、QQ 号**，提交后页面就会通过 RCON 把白名单加到服务器上，并切换到「恭喜，白名单已添加」；同时（可选）给管理员发一条通知（邮件 / HTTP 回调 / QQ 机器人），带上这位玩家的游戏方式与 QQ 号，方便管理员联系与核对。

**主要目的是防机器人**：把这道「填写 ID 并提出申请」的关卡放在服务器门外，恶意破坏服务器的机器人扫描到端口后无法直接进服捣乱，也留下了一条申请记录可供追溯。

> 一个 Kalmia 插件：用 WebSocket RCON 连上 Minecraft 服务端，再对外提供一个**玩家自助申请页** + HTTP API，用来把玩家加进白名单（另有一个面向管理员的移出接口）。

服务端侧只用到 RCON（默认 `127.0.0.1:25575`），无需在 Minecraft 服务端装 Fabric/Forge 模组；申请页面本身跑在 Kalmia 的 HTTP 服务上（默认 `12345` 端口）。对端的形态要求见 [前置条件](getting-started.md#前置条件)。

管理员通知是**可选**的：默认关闭（`notify.enabled = false`），不配置就完全不发任何通知，也不产生额外网络请求。

## 功能特性

- **玩家自助申请页**：单页表单（`assets/index.html`），填**游戏内名称 / 游戏方式 / QQ 号**三项即可提交，不需要记任何命令，也不暴露管理功能；玩家自行申请、无需管理员在场，这是抵御恶意破坏机器人的第一道门
- **提交即生效**：校验通过后立刻通过 RCON 执行 `/whitelist add <name>`，成功后切到「恭喜，白名单已添加」的结果页
- **前后端双重校验**：名称（3-16 位字母数字下划线）、游戏方式（正版 / 皮肤站）、QQ 号（5-11 位数字）在浏览器和插件里各校验一次；非法输入返回 `400` 并在页面上标红对应字段，不会发出 RCON 命令
- **可选的申请通知**：玩家提交后，可选地通过**邮件 / HTTP 回调 / QQ 机器人**三种渠道之一或多种通知管理员，通知里带上游戏方式与 QQ 号；默认关闭，缺省不产生任何外部请求
- **页面可在线更新**：启动时从配置的 URL 拉取最新的 `index.html`，改前端不必重新构建、重新部署插件；是否下载、下载地址都写在配置文件里
- **HTTP API**：两个 `POST` 接口（申请 / 移出），页面与脚本走同一套接口
- **自动重连**：RCON 断开后自行重连并重新认证，退避到 30 秒上限；服务端重启、掉线都不需要人工干预
- **页面不被 RCON 拖死**：RCON 未就绪时接口返回 `503` 且页面照常可访问，不会因为 RCON 连不上而启动失败
- **reload / stop 安全**：接上 Kalmia 的 reload/stop 监听器，插件重载或关闭时会主动断开，不残留 socket 与事件循环线程
- **健壮的报文解析**：畸形、截断、类型未知的 RCON 帧一律忽略，不会把插件打崩
- **参数可配置**：RCON 地址/端口/密码、页面下载与通知渠道都在 `configs/quizpass.json`，改配置即可，无需重新构建
